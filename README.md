# Мої слова — версія 2.0 з Supabase

Особистий англійський словник і квіз EN↔UK. Статичний сайт для GitHub Pages та iPhone PWA. Синхронізація слів через Supabase після входу; локальна робота та JSON-копії залишаються доступними без входу. Без збірки, встановлення пакетів, CDN або окремого сервера.

## Оновити твій уже опублікований сайт

1. **На iPhone через іконку старого застосунку:** Копія → Завантажити JSON. Перевір, що файл є у «Файли». Збережи копію й на Mac за бажанням.
2. Розпакуй новий ZIP. На GitHub відкрий **той самий** репозиторій `my-vocabulary` → **Add file → Upload files**.
3. Завантаж увесь вміст ZIP у корінь репозиторію, разом із папкою `icons`. Файли з однаковими назвами буде оновлено. Папку-обгортку та сам ZIP завантажувати не потрібно. Якщо `.nojekyll` прихований, його можна пропустити. Натисни **Commit changes**.
4. Дочекайся успішної публікації GitHub Pages. Налаштування **main / (root)** залишаються ті самі.
5. На iPhone відкрий застосунок через його наявну іконку з інтернетом. Через деякий час з’явиться повідомлення **«Доступне оновлення»** → натисни **«онови застосунок»**. Якщо повідомлення не з’явилося, закрий застосунок і відкрий ще раз з інтернетом. **Не видаляй іконку та не очищай дані Safari.**
6. У новій версії відкрий **Вхід / копія**. Введи пошту та пароль **користувача словника, якого створили в Authentication → Users**, а не пароль бази даних і не пароль входу в панель Supabase.
7. Після першого входу локальні слова автоматично додадуться до хмарного словника. Дочекайся статусу **«Синхронізовано»**. Якщо там уже є точні дублікати карток, вони об’єднаються.
8. На Mac відкрий `https://mykytahaponov.github.io/my-vocabulary/`, онови сторінку, перейди у **Вхід / копія** та увійди з тією самою поштою і паролем. Натисни **Синхронізувати ↻** за потреби. Ті самі слова мають з’явитися на Mac.

**Таблицю в Supabase вже створено. SQL повторно запускати не потрібно.** Адреса твого проєкту й публічний ключ уже внесені в `config.js`; файл `.env` не потрібен. Пароль і секретні ключі у файли сайту не записуються.

## Як працює синхронізація

- Передаються англійські слова/вирази, українські переклади та видалення. Результат останнього квізу й незавершена сесія залишаються локальними на кожному пристрої.
- Слова спочатку записуються на пристрій. Після входу, зміни, повернення у застосунок, відновлення інтернету та приблизно кожні 30 секунд у відкритому застосунку виконується синхронізація. Є ручна кнопка. На закритому iPhone фонової синхронізації немає.
- Без інтернету можна працювати з уже завантаженим словником. Непередані зміни зберігаються між перезапусками й передаються при наступному відкритті з інтернетом. Перший вхід на новому пристрої потребує інтернету.
- Статус **«Синхронізовано»** підтверджує завершення останнього обміну, а не безперервний зв’язок. Щойно внесені на іншому пристрої зміни з’являться під час наступного обміну.
- Одночасне редагування або редагування проти видалення одного слова створює конфлікт. У **Вхід / копія** видно обидві версії: **Залишити мою** передає поточну локальну версію; **Взяти з хмари** замінює її хмарною. Перед вибором можна експортувати JSON локальної версії. Інші слова продовжують синхронізуватися.
- Видалені слова залишають технічну позначку у хмарі, але не показуються у словнику. Вона потрібна, щоб старий офлайн-пристрій не повертав видалення назад.
- Вихід зупиняє синхронізацію та прибирає збережений сеанс входу; локальний словник залишається доступним. Для іншого акаунта використовуй окремий профіль браузера. Це персональний застосунок для власних пристроїв.
- Якщо словник відкрито у двох вкладках одного браузера, після змін в іншій вкладці застосунок попросить перезавантажити поточну, щоб не затерти її дані.

## Перша перевірка iPhone ↔ Mac

1. На iPhone увійди й дочекайся **«Синхронізовано»**. На Mac увійди тим самим користувачем і перевір слово.
2. На Mac додай `rain` → `дощ`, дочекайся синхронізації. На iPhone натисни **Синхронізувати ↻** — слово має з’явитися.
3. Відредагуй переклад на одному пристрої та перевір інший. Так само перевір видалення непотрібної тестової картки.
4. На iPhone спочатку дочекайся **«Готово до роботи офлайн»**, потім увімкни авіарежим і додай слово. Воно має залишитися після перезапуску. Поверни інтернет, відкрий застосунок та синхронізуй. Перевір на Mac.

Якщо вхід не вдається: перевір пошту, пароль та підтвердження користувача в Supabase. Якщо повідомлення вказує на завершення сеансу, вийди та увійди повторно. Якщо Supabase призупинив безкоштовний проєкт, віднови його в панелі Supabase та повтори синхронізацію. Локальні слова при цьому залишаються доступними.

## Словник, квіз і копії

- Ручне додавання, пошук, редагування, видалення. До 5000 активних карток, до 500 символів у кожному полі. Фактичний обсяг обмежує також сховище браузера.
- Варіанти відповіді розділяй `;`: `затоплювати; затопити`. Кома залишається частиною виразу. У запитанні показується перший варіант.
- Квіз лише з ручним введенням: EN→UK або UK→EN, до 10 / до 20 / усі картки у випадковому порядку.
- Перевірка ігнорує регістр, зайві пробіли, кінцеві `. ! ? …`, типографічні відмінності апострофів і тире, а для англійської — початкове `to`. `TO FLOOD!` приймається як `flood`, але `flod` — ні. Автоматичного словника синонімів немає. Можна вручну зарахувати свою відповідь.
- Є підсумок, список помилок і повторення помилок. Незавершений квіз після закриття не відновлюється.
- Експорт JSON містить активні слова та підсумок останнього квізу, **без сеансу входу й технічних даних синхронізації**. Старі JSON-копії сумісні.
- Імпорт **Додати** зливає картки та пропускає точні дублікати. **Замінити** після підтвердження замінює локальний список; після синхронізації редагування й видалення поширяться на інші пристрої. Спочатку експортуй поточний список. Файл до 32 МБ, некоректний файл відхиляється повністю.

Safari та встановлений PWA можуть мати окремі локальні дані: увійди в однаковий акаунт у потрібних місцях. Очищення даних, приватний режим, видалення PWA чи нестача місця можуть видалити локальні та ще не синхронізовані слова. Хмарне збереження не замінює JSON-копію.

## Безкоштовний план і приватність

Сайт залишається на GitHub Pages. Supabase Free має квоти та може призупинити проєкт за низької активності. Безстрокову доступність безкоштовного плану не гарантовано. UptimeRobot у цій версії ще не налаштований.

Слова надсилаються тільки у налаштований Supabase після входу. GitHub зберігає код. Пароль передається Supabase через HTTPS під час входу й не зберігається застосунком; сеанс входу зберігається локально. Публічний ключ у `config.js` призначений для браузера. Захист даних забезпечують вхід і RLS на таблиці. Не додавай secret/service_role ключ у код або GitHub.

- https://supabase.com/docs/guides/getting-started/api-keys

## Перевірки та подальші оновлення

Автоматичні тести без зовнішніх пакетів: `node tests/check.mjs` (Node.js 18+). Папка `tests` є у вихідній робочій папці; для публікації не потрібна й у цьому ZIP не включена. `supabase/001-vocabulary.sql` у вихідній папці — вже виконана початкова схема, теж не потрібна для завантаження на GitHub Pages.

Пройдено 15 груп тестів: початкові функції словника/квізу/JSON/PWA, тристороннє злиття, два змодельовані пристрої, офлайн-черга, одночасне редагування, конфлікти з видаленням, загублена відповідь INSERT, зміни під час запиту, поділ акаунтів, оновлення сеансу, пагінація понад 1000 записів і перевірка полів відповідно до SQL-дозволів. UI перевірено в моделі DOM, API — на моделі Supabase, кеш — на моделі Cache API. Це не перевірка справжньої бази чи Safari. Фактичний вхід, RLS, встановлення PWA та синхронізацію на iPhone потрібно перевірити після публікації за кроками вище.

Для кожного наступного оновлення кешованих файлів збільшуй `VERSION` у `sw.js`. Не змінюй адресу сайту й ключ локального сховища без перенесення даних. Розпакований ZIP можна опублікувати і як новий сайт: **Settings → Pages → Deploy from a branch → main → /(root) → Save**.
