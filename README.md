# Мої слова · v3.4.0 — прогрес слів

## Як оновити

1. На iPhone та MacBook натисни «Синхронізувати». У «Налаштуваннях» збережи JSON-копію.
2. Відкрий свій проєкт Supabase → **SQL Editor → + → Create a new snippet**. Відкрий `01-add-progress.sql` текстовим редактором, скопіюй ВЕСЬ вміст, встав у snippet та натисни **Run**. Очікується Success. Це окрема таблиця історії повторень; старі слова не змінюються. Скрипт можна виконувати повторно.
3. Розпакуй `vocabulary-progress-site-v3.4.0.zip`. ВІДКРИЙ отриману папку: всередині мають бути `index.html`, `app.js`, `progress.mjs`, `sw.js`, `icons` тощо.
4. На головній сторінці існуючого репозиторію **my-vocabulary** натисни **Add file → Upload files**. Перетягни ВМІСТ цієї папки поверх старих файлів. Не додавай папку-обгортку. Натисни **Commit changes**. Старі файли заздалегідь видаляти не потрібно. SQL і tests у GitHub завантажувати не потрібно.
5. Дочекайся успішної публікації GitHub Pages у вкладці Actions. Відкрий https://mykytahaponov.github.io/my-vocabulary/ з інтернетом, за потреби закрий та відкрий застосунок і підтвердь **Оновити застосунок**. У Налаштуваннях має бути **v3.4.0**. Зроби це **на обох пристроях до нової практики**. Іконку застосунку не видаляй, Safari не очищай.
6. Mac Helper та його авторизацію змінювати не потрібно. У цьому оновленні немає запитів до ШІ.

## Перша перевірка

1. У Практиці вибери EN → UK й відповідай на одне слово. Після перевірки з’явиться «Правильно 1 із 1 · поспіль 1» та дата повторення. Відповідь уже збережена, навіть якщо не завершиш квіз.
2. У Словнику розгорни прогрес цього слова: EN → UK матиме одну спробу, UK → EN — нуль.
3. Натисни «Синхронізувати». Відкрий застосунок на іншому пристрої й синхронізуй його: прогрес має збігтися.
4. Для повторного тренування того самого слова до дати повторення вибери **Усі слова**. Правильна відповідь додасться до лічильника, але не підвищить рівень завчасно.
5. Якщо відповідь правильна за змістом, але не збігається з внесеним перекладом, натисни «Зарахувати мою відповідь». Це виправить результат однієї спроби, а не додасть другу. За потреби потім додай цей переклад як допустимий варіант у картці.
6. Перевір JSON-експорт: окрім слів, він тепер містить `reviews`. Повторний імпорт тієї самої копії не подвоює прогрес.

## Як працює прогрес

Для кожної картки та кожного напрямку окремо зберігаються всі перевірені спроби, правильні відповіді, послідовність правильних відповідей та дата повторення. Введений текст відповіді до хмарної історії не записується: лише результат, напрямок, час і версія слова/перекладу.

- Нове — спроб поки немає.
- Вчу — початок практики або повторне закріплення після помилки.
- Закріплюю — пройдено 2–4 повторення з перервами.
- Засвоєно — 5 правильних повторень із потрібними перервами. Це умовний орієнтир, не гарантія знання.
- Час повторити — настав час нового повторення. Ти сам вирішуєш, коли тренуватися.

Після першого правильного пригадування — 1 день до повторення, далі 3, 7, 14 і 30 днів. Після досягнення рівня «Засвоєно» наступні правильні планові повторення залишають інтервал 30 днів. Рання практика збільшує статистику, але не скорочує ці інтервали. Помилка або «Не пам’ятаю» обнуляє тільки поточну послідовність і рівень повторення; усі попередні спроби залишаються. Слово доступне для планового повторення через 10 хвилин; для негайного повторення доступні «Повторити помилки» та «Усі слова».

«Повторення та нові» пропонує спершу слова, для яких настав час повторення, далі нові. Усередині цих груп порядок випадковий. Якщо все вже повторено, можна обрати «Усі слова» або повернутися пізніше.

Немає календарних серій, цілей на день, оцінок за пропуски чи нагадувань. Показник «поспіль» стосується відповідей на ОДНЕ слово, а не днів практики.

## Збереження та сумісність

- Прогрес рахується **від цього оновлення**. Старий підсумок квізу містить лише загальний результат, тому з нього неможливо відновити спроби кожного слова.
- Прогрес зберігається після кожної перевірки, локально без інтернету; після входу та синхронізації переноситься між iPhone й MacBook.
- Повторення з двох пристроїв об’єднуються за унікальними ID, без перезапису лічильників. Повторна відправка після збою не дублює спробу.
- Зміна слова або перекладу починає статистику для нового значення; старі події зберігаються. Зміна категорії, частини мови, Pattern, прикладів або примітки не скидає прогрес. Повернення точної попередньої пари слова/перекладу знову показує її історію.
- При імпорті точні дублікати карток можуть мати різні ID: їхня історія відображається разом. Видалене й заново додане з тією самою парою слово також може отримати попередню історію. Заміна словника з JSON замінює слова, але **об’єднує** історію: вона не стирає практику з інших пристроїв. Старі копії без історії читаються.
- Останній підсумок квізу залишається локальним, як раніше.
- Час повторень залежить від правильного годинника пристрою.
- Перша версія історії розрахована на 30 000 подій (ручне зарахування додає службову подію). Safari може вичерпати локальне сховище раніше: застосунок повідомить про помилку збереження, а не позначить відповідь збереженою. Зберігай JSON-копії. Не використовуй стару версію сайту для нової практики: вона ще не вміє зберігати історію.

## Перевірка розробки

14 автоматичних перевірок (Node.js 22+, без встановлення пакетів):

```sh
node --test tests/*.test.mjs
```

Перевірено лічильники й інтервали, розділення напрямків, ручне зарахування без подвійного підрахунку, пропуски, старі/нові JSON-копії, повторний імпорт, зміну значення, реальні обробники квізу на моделі DOM, збереження після виходу, відмову сховища, синхронізацію двох пристроїв, відповідь під час відправки та повтор після втраченої мережевої відповіді. Також перевірено синтаксис JS, HTML-ID й склад офлайн-кешу.

Це локальні тести з моделлю DOM та штучними відповідями мережі. Локальний вебсервер недоступний у цьому середовищі, тому візуальна перевірка в Safari не виконана. SQL підготовлено, але він не запускався у твоєму живому Supabase; оновлення на GitHub не публікувалося. Першу перевірку після встановлення наведено вище.

RLS-політики таблиці історії дають тільки SELECT та INSERT для власних записів авторизованого користувача. Оновлення й видалення через клієнт заборонені правами. Використаний підхід до grants/RLS: https://supabase.com/docs/guides/database/postgres/row-level-security
