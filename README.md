# Мої слова — особистий vocabulary quiz

Готовий статичний PWA для iPhone. HTML, CSS і JavaScript без встановлення залежностей, акаунта, сервера, бази даних чи платних сервісів. Словник спочатку порожній.

## Опублікувати на GitHub Pages

1. Розпакуй ZIP на комп’ютері. Створи на GitHub новий **публічний** репозиторій, наприклад `my-vocabulary`.
2. У репозиторії натисни **Add file → Upload files**. Завантаж **вміст розпакованого ZIP**, а не сам ZIP і не папку-обгортку. `index.html`, `app.js`, `core.mjs`, `styles.css`, `sw.js`, `manifest.webmanifest` та папка `icons` мають бути в корені репозиторію. `README.md` і `tests` можна також завантажити. Прихований `.nojekyll` бажано додати, але для цих файлів він не обов’язковий.
3. Натисни **Commit changes** у гілку `main`.
4. Відкрий **Settings → Pages → Build and deployment**.
5. У **Source** обери **Deploy from a branch**. Нижче: **main** і **/(root)** → **Save**.
6. Дочекайся успішної публікації (стан видно також у вкладці **Actions**). Відкрий адресу, яку покаже Pages: `https://ТВІЙ-ЛОГІН.github.io/my-vocabulary/`.
7. На iPhone відкрий цю адресу в **Safari → Поділитися → На початковий екран / Add to Home Screen → Додати**. Якщо є перемикач **Open as Web App**, залиш його увімкненим. Запусти «Мої слова» з нової іконки з інтернетом і дочекайся напису **«Готово до роботи офлайн»**. Тепер додавай свої слова.

Не потрібно завантажувати код у якийсь додатковий сервіс. Усі шляхи відносні, тому сайт працює як у корені домену, так і в підпапці репозиторію. Відкриття `index.html` подвійним кліком через `file://` не є підтримуваним запуском: модулі та PWA потребують HTTPS або локального HTTP-сервера.

Офіційна інструкція GitHub: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Як користуватися

- **Словник:** введи англійське слово/вираз та український переклад. Додай, редагуй, шукай або видаляй картки. Видалення потребує підтвердження.
- **Варіанти:** `flood` → `затоплювати; затопити`. Роздільник — `;` (або перенесення рядка в імпортованому файлі); кома є частиною відповіді. Варіанти можна вказувати в обох полях. У запитанні відображається перший варіант.
- **Практика:** обери EN→UK або UK→EN та до 10, до 20 чи всі слова. Якщо слів менше, квіз візьме всі доступні. Кожна картка з’являється один раз у випадковому порядку.
- Введи відповідь → **Перевірити** → **Наступне слово**. Варіантів відповіді немає. **Не пам’ятаю** рахується як помилка.
- Перевірка ігнорує регістр, зайві пробіли, кінцеві `. ! ? …`, типографічні відмінності апострофів і тире, а для англійської — початкове `to`. `TO FLOOD!` приймається як `flood`, але `flod` — ні.
- Перевірка не використовує AI чи словник синонімів. Написання, решта пунктуації та форми слова мають збігатися з одним із твоїх варіантів. Якщо відповідь доречна, але не внесена, натисни **Зарахувати мою відповідь**, а згодом відредагуй картку. Це не змінює її автоматично.
- Після квізу є оцінка, список помилок і **Повторити помилки**. Дострокове завершення враховує лише перевірені відповіді. Зберігається короткий підсумок останнього квізу; незавершена сесія після закриття не відновлюється.

## Резервна копія та iPhone

**Копія → Завантажити JSON**. Перевір, що файл збережено у «Файли» / «Завантаження», і за бажанням перенеси його в iCloud Drive. Зроби копію після важливих змін.

Для відновлення: **Копія → вибрати JSON → Додати до мого словника** або **Замінити весь словник → Імпортувати**. Додавання пропускає точні дублікати карток; інший переклад того самого слова може утворити окрему картку. Заміна потребує підтвердження та відновлює також підсумок із копії; додавання залишає поточний підсумок. Некоректний файл відхиляється повністю. Обмеження: 5000 карток, до 500 символів у кожному полі та файл до 32 МБ; фактичний обсяг словника також обмежує доступне сховище браузера.

Дані зберігаються в `localStorage` цього браузера/вебзастосунку. GitHub зберігає лише код, не твої слова. Safari та встановлений PWA можуть мати окремі сховища: **спочатку встанови сайт, потім наповнюй словник через його іконку**. Для перенесення між ними чи на інший пристрій використовуй JSON.

Очищення даних сайту, приватний режим, видалення вебзастосунку, обмеження сховища та дії iOS можуть зробити локальні дані недоступними. Встановлення на початковий екран не замінює резервну копію. WebKit окремо описує виняток Home Screen web apps із 7-денного правила ITP, тому автоматичне видалення рівно через 7 днів не слід вважати загальним правилом для встановленого PWA.

Джерела WebKit:
- https://webkit.org/blog/14403/updates-to-storage-policy/
- https://webkit.org/tracking-prevention/
- https://webkit.org/blog/14787/webkit-features-in-safari-17-2/

Залишай ту саму адресу сайту: зміна домену чи шляху означає інше сховище. Звичайне оновлення коду на тій самій адресі не стирає словник. Якщо запис не вдався, сайт повідомить про це й не покаже зміну як збережену. Пошкоджені дані можна окремо завантажити перед відновленням копії.

## Швидка перевірка після публікації

1. Запусти через іконку iPhone, додай `flood` → `затоплювати; затопити`. Закрий і знову відкрий: картка має залишитися.
2. Пройди обидва напрямки: `затопити` й `to flood` мають прийматися, `flod` — показати помилку.
3. Експортуй JSON, перевір його у «Файли», а потім імпортуй у режимі додавання: дубль не має з’явитися.
4. Дочекайся «Готово до роботи офлайн», увімкни авіарежим, закрий і відкрий PWA. Словник та квіз мають працювати.

## Оновлення коду

Заміни файли в тому самому репозиторії та збільш `VERSION` у `sw.js` (наприклад, до `v1.0.1`) **після будь-якої зміни кешованих файлів**. Дочекайся GitHub Pages. Відкрий застосунок з інтернетом; коли з’явиться повідомлення про оновлення, заверши поточну роботу й натисни «онови застосунок». Не потрібно видаляти PWA чи очищати дані Safari.

## Перевірки для розробника

За наявності Node.js 18+: `node tests/check.mjs`.

Дев’ять груп автоматичних перевірок пройдено: нормалізація відповідей, валідація копій, злиття, вибір слів, сценарії словника/квізу/JSON, збої сховища та логіка service worker. Сценарії інтерфейсу виконані в моделі DOM; кеш — у моделі Cache API. Це не запуск реального Safari. Встановлення PWA, вигляд, завантаження у «Файли» та фактичний офлайн-режим на iPhone потребують короткої ручної перевірки вище.
